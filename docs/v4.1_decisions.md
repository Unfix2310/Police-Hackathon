## §22 — InteractionEvent canonical contract ✅ IMPLEMENTED

**Decision:** Implement `InteractionEvent` as a first-class DB table (not derived data).

- **Why:** v3 stored only raw observations + entity links. Computing relationships at query time was too slow and couldn't support live stream workload.
- **File:** [`backend/models/interaction.py`](../gujarat-cctv-platform/backend/models/interaction.py)
- **Key fields:** `event_type`, `interaction_class`, `generic_lifecycle`, `domain_state_before`, `domain_state_after`, `reason_codes`, `evidence_obs_ids`, `end_time`
- **Note:** `end_time` is populated by `_persist_event()` when a terminal state (EXITED/ENDED/POSSIBLE_EXIT) fires — it back-fills the most recent open RIDING_IN event for the same (subject, object) pair.

## §10 — Person–Vehicle State Machine ✅ IMPLEMENTED

**Decision:** 8-state machine in `PersonVehicleStateMachine`. One instance per `(person_id, vehicle_id)` pair, held in memory per-process.

| State | Trigger | Notes |
|:------|:--------|:------|
| UNKNOWN → POSSIBLE_PROXIMITY | `proximity_score > 0.50` | |
| POSSIBLE_PROXIMITY → POSSIBLE_ENTRY | `overlap_score > 0.40` | |
| POSSIBLE_ENTRY → ENTERED | `overlap_score > 0.70` | |
| ENTERED → RIDING_IN | immediate on next frame | auto-transition |
| RIDING_IN → POSSIBLE_EXIT | `proximity_score < 0.65` | **Fix 1a** — wired into `update()`, not just external trigger |
| POSSIBLE_EXIT → EXITED | `proximity_score < 0.30` | |
| EXITED → ENDED | `proximity_score < 0.30` on next frame | **Fix 1b** — new branch |
| EXITED → POSSIBLE_PROXIMITY | person returns | return-to-vehicle edge case |

**End-time close (Fix 1c):** `_persist_event()` stamps `end_time` on the prior open RIDING_IN/ENTERED row when a terminal event fires.

## §25 — Hypothesis contract ✅ IMPLEMENTED

**Decision:** All correlation output is wrapped as `Hypothesis` with `status=GENERATED` and `requires_human_review=True`. Status can only progress via an authenticated officer review (`POST /api/v1/hypotheses/{id}/review`).

**Officer review decisions:** `ACCEPTED` | `REJECTED` | `DEFERRED`

> [!IMPORTANT]
> A hypothesis that remains `GENERATED` or `PENDING_REVIEW` **must not trigger any enforcement action**.
> This is a hard architectural constraint, not a UI suggestion.

## §23 — Temporal Investigation Graph ✅ IMPLEMENTED

**Decision:** Replace `nx.Graph()` (static, undirected) with `nx.MultiDiGraph()` (directed, temporal, parallel edges).

**Fix 2 — bidirectional DB query:** `_fetch_events_for_entity()` and `get_entity_relationship_history()` previously only queried `subject_entity_id`. A vehicle queried as root would see zero passenger edges because persons are always the *subject*. Fixed with `OR(subject=eid, object=eid)` and bidirectional frontier discovery.

**Supported queries (all passing in test suite):**
1. `who_was_in_vehicle_at(vehicle_id, at_time)` — occupants at a point in time
2. `get_entity_vehicles(entity_id)` — all vehicles a person used
3. `shared_passengers(vehicle_a, vehicle_b)` — multi-hop vehicle switch detection
4. `get_entity_timeline(entity_id)` — chronological relationship history

## §24 — Five-Way Camera Gap Semantics ✅ IMPLEMENTED

**Decision:** Replace binary `online/offline` with 5-state `ObservationStatus` enum.

| Code | Meaning | Engine rule |
|:-----|:--------|:------------|
| `OBSERVED_PRESENT` | Camera active, entity detected | Positive evidence |
| `OBSERVED_ABSENT` | Camera active, entity NOT seen | Positive absence |
| `NOT_OBSERVED` | No camera coverage | **Cannot conclude anything** |
| `CAMERA_OFFLINE` | System fault | Log, no inference |
| `UNKNOWN` | Degraded / occlusion | Flag for review |

**Critical rule:** `NOT_OBSERVED` ≠ `OBSERVED_ABSENT`. The hypothesis engine must not use `NOT_OBSERVED` gaps as evidence of absence.
